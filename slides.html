Universal Dependencies（UD）とは

  • 依存文法に基づく、通言語的に一貫した形態・統語アノテーション枠組み
  • 180 以上の言語、300 以上のツリーバンク（v2.17）

UD の基本原則

  1. 語（word）ベースのアノテーション
  2. 語の内部構造 → FEATS で記述
  3. 品詞 → UPOS、依存関係 → DepRel

UDJ の 3 つの根本的問題

UDJ は学校文法（GB）に基づく仮名ベースの分析を採用
→ UD の「語ベース」原則と根本的に矛盾

#問題内容
1トークン化形態素レベルの分割（語レベルではない）
2FEATS形態論的特徴の記述がほぼゼロ
3DepRel依存関係ラベルの不適切な仕様

以下、takaku nakatta（高くなかった）で全問題を図示する

問題 1 トークン化

UDJ：形態素 3 トークン（高く・なかっ・た） → MUDJ：語 2 トークン（taka-ku・na-kaQta）

問題 2 FEATS（形態論的特徴）の欠如

UDJ では FEATS ≈ 0% → 日本語が「孤立語」に見える致命的な問題

問題 3 DepRel の不適切な仕様

UDJ：cop / advmod / aux を全て aux に → 英語との対比が不可能

先行研究 Taguchi & Chiang (2023) の成果

UDJ のトークン化・FEATS 問題に正面から取り組んだ先駆的研究

  • XPOS で助動詞を検出し先行トークンにマージ
  • 文法機能を FEATS として記録

→ 現行 UDJ が日本語の形態的類型を
根本的に誤表示していることの定量的証拠

先行研究 アルゴリズムと問題点

いらっしゃら＋なかっ＋た → irassyara-nakat-ta (1語) OK
高く＋なかっ＋た → *takakunakatta (1語) NG（正：2語）

問題：束縛形態素か自立語かを区別せず、形態的複雑さが過大評価されがち

比較 GSD / Taguchi / MUDJ

GSD：3 形態素トークン・FEATS なし｜Taguchi：1 トークン・DepRel 消失｜MUDJ：2 語・FEATS 付与・DepRel 維持

提案 MUDJ の基本方針

GB の語分割を完全に放棄し、言語学的に妥当な語ベースの分割に自動変換

Matomonizer パイプライン（5 フェーズ）

Phase処理例
P0MWT 展開じゃ → で＋は
P1Chain 統合ている → 2 語として統合
P2接辞マージた・ない・ます → 語内部に統合
P3aUPOS / DepRel 修正は → PART / advmod
P3b音韻変換 + FEATS + Glosskana → phoneme、特徴付与

matomo=na（まともな）＝「ちゃんとした」の意

プロジェクトの全体像

UDJ → MUDJ → 形態素対応表 → 方言・琉球諸語 UD の自動構築

現状と今後の課題

現時点は試行錯誤の段階であり、かなり不完全

  • 動詞・形容詞・助動詞周りが中心；名詞周りはほぼ手付かず
  • ただし名詞の処理は比較的単純であり、拡張は容易

今後の展望

  1. 名詞・副詞等への Feats / Gloss ルールの拡充
  2. 機械学習による自動化：
    　　Matomonizer の出力を教師データとして、retokenization・UPOS・DepRel を自動予測するモデルの構築
  3. 方言・琉球諸語 UD の自動構築

まとめ

  1. UDJ は3 つの根本的問題を抱える
    　　トークン化・FEATS 欠如・DepRel 不備
  2. Matomonizer：GB を放棄し、語ベースの分割に自動変換
  3. MUDJ：FEATS +34pp、Gloss 49%、DepRel 適正化
  4. 今後：名詞拡充 → ML による自動化 → 方言・琉球諸語 UD
