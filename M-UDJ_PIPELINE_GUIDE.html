M-UDJ PipelineGSD (仮名) → M-UDJ (phonemic alphabet) 変換パイプライン

日本語 Universal Dependencies コーパス (GSD) の仮名表記・不適切な形態素分割・feats不足を、ユーザー定義の187パターンに基づいて体系的に修正し、phonemic alphabet ベースの新コーパス M-UDJ を生成する。

2教師データのワークフロー

パイプラインの変換ルールは、ユーザーが2つのHTMLツールで定義し、JSONとして書き出す。パイプラインはこのJSONを読み込んで自動適用する。

① UDJ_v2.html — パターンアノテーション

日本語文法の187パターンをバッチごとに表示し、各パターンに以下を記入する：

フィールド内容例 (ている)
phonphonemic表記（トークン分割はスペース）tabe-te i-ru
glossLeipzig gloss（-で形態素境界）食べる-SEQ PROG-PRS
ov各トークンのUPOS/deprel/feats overridetok1: {upos:AUX, head:1}
出力: udj_v2_annotations.json → v2_to_v5.py → decisions_full.json に統合
② affix_editor.html — Affix定義とトークン境界

各接辞（た・ない・ます・れる等）について以下を定義する：

タブ編集内容
Affix Definitions各接辞の活用形ごとの phon / seg / gloss / feats（例: ta → PST, tara → CND）
Stacking Patterns接辞の積み重ねパターンとトークン分割の正解（例: V+CAUS+PASS+PST → tabe-saserareta）
Token Boundaries各接辞の後でトークンが切れるか（例: -te → ✂yes, jd.ta → →no）
出力: affix_rules.json → パイプラインの Phase 2a が読み込む
③ mudj_editor.html — 出力精査

パイプライン出力の M-UDJ CoNLL-U を閲覧し、依存構造図を確認しながら手動修正する。ExtPOS編集にも対応。

4各フェーズの詳細

Phase 0: MWT展開

口語の縮約形を分析的な形に展開する（CoNLL-U Multiword Token形式）。

じゃ → で + は   zya → de + wa
ちゃう → て + しまう   tyau → te + simau

Phase 1: Chain統合

GSD で fixed 関係で連なっている機能語連鎖を統合する。te_aspect系（ている、てくる等）は2トークン（verb-te + AUX）、compound系（ので、について等）は1トークンに統合。

te_aspect → 2tok
食べ + て + いる → tabe-te + ir-u   VERB + AUX/aux
決め + て + い + た → kime-te + i-ta   verb-te + AUX(PST)

compound → 1tok
の + で → no+de   SCONJ/mark CAUS.SEQ
に + つい + て → ni+tui+te   ADP/case TOPIC
と + し + て → to+si+te   ADP/case ROLE

Phase 2a: Affix統合

GSD で独立トークン扱いの接辞（「助動詞」）を、先行する動詞・形容詞に結合する。affix_rules.json の seg フィールドが形態素境界の真実源。

カナ → phonemic + seg 変換フロー（例: 叫ば + れ）
GSD入力:  叫ば(VERB,五段バ行)  +  れ(AUX, lemma=れる)

Step 1  k2p():          サケバ → sakeba,    レ → re
Step 2  stem_split():   sakeba → sakeb-a    (五段バ行: 子音+活用母音)
Step 3  LEMMA_DEC:      れる → jd.reru     (rule_table.lemma_dec)
Step 4  godan prepend:  stem末尾'a' + 're' = 'are'
Step 5  seg_lookup:     jd.reru|are|godan → seg='are'  (affix_rules.json)
Step 6  vowel strip:   sakeb-a → sakeb     (stem から connecting vowel を除去)
Step 7  join:          sakeb + '-' + are = sakeb-are
Step 8  gloss/feats:   PASS / Voice=Pass  (affix_rules.json)
食べ + た → tabe-ta   Tense=Past PST
叫ば + れ → sakeb-are   Voice=Pass PASS
食べ + ます → tabe-mas-u   Polite=Form|Tense=Pres POL-NPST
触れ + られ + なかっ + た → hure-rare-na-kaQta
    Voice=Pass|Polarity=Neg|Tense=Past PASS-NEG-PST

※ サ変する（攻撃+し+て+くる）は affix merge 対象外: Phase 1.5 で N(→VERB) + する(AUX) の2トークン構造に変換

Phase 2b: SCONJ suffix統合

接続助詞の「て」「ば」を先行動詞に結合する（ただし chain の一部は除外）。

思い切っ + て → omoikiQ-te   VerbForm=Conv SEQ
叫ばれ + て → sakeb-are-te   Voice=Pass|VerbForm=Conv
※ て+いる, て+しまう 等はchain扱いのため結合しない

Phase 3a: UPOS/DepRel修正

ユーザーのJSON定義に基づき、GSD のラベルをUD標準に修正する。

9残課題

stem_split() → JSON逆算
49行のハードコード。affix_rules.json の seg フィールドから形態素境界を逆算する設計。最難関。
Feats 65%未付与
名詞・副詞等にfeatsルールが少ない。feats_mapの拡充（v2パターン追加）で改善可能。
assign_gloss fallback
154行中97.8%はrule_table解決済み。残り37パターン（DET/CCONJ）はL4で対応済み、要テスト。
ExtPOS未反映
v2 ov に16パターンのExtPOS定義あり。未実装。
に DAT/LOC判別
で LOC/INS と同様のヒューリスティック。将来ML置換候補。
Round-trip検証
backward_retokenizerのdeferred-te・サ変する対応が必要。
